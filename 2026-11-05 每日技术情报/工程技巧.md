## 二、关键洞见

### 1. 验收单位应从“一次成功”扩展到“连续变更与失败恢复”

跨来源推断： 代码库需要延续历史约束，研究任务需要更新假设，持久 Agent 需要恢复状态，多 Agent 需要处理交接失败。共同的工程问题是：系统在任务发生变化或执行中断后，能否继续产出正确结果。因此，试点应包含连续改需求、中断恢复和失败重试，记录成功率、返工量、审查耗时及恢复成本。【Agent 的能力还不足维护代码库！HumanLayer 创始人质疑“无人值守”的软件工厂】【高德 Data Agent 实践：从数字到业务决策（下篇）】【openJiuwen 首发蜂群架构 Hyper-Agent，开启 Agent 组织级协作新范式！】【AI 智能体集群在《我的世界》中「建立繁荣文明」——50 个智能体组成的团队因陷入瘫痪性官僚主义而失败】
