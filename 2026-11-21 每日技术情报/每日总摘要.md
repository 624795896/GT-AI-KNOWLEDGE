### 1. “有依据地完成任务”正在成为 Agent 的独立验收维度

材料事实： Gemini 团队核对行动轨迹与完成汇报，并奖励如实说明部分完成；LiveX Wiki 区分已核实知识与未核实信息，并要求回源确认。两者都将证据核验纳入工作流。【Gemini 4 怎样训练到能做真实工程任务，Google DeepMind 的 Melvin Johnson 详解】【基于 LLM Wiki、OKF 与 Git 的 Agent 知识库：淘宝直播互动团队的 AI Coding 实践】

跨来源分析： Agent 的结果正确性与汇报可信度应分别评估。企业可以将完成声明关联到测试结果、代码版本和执行记录，并保留“部分完成、仍待验证”的状态，减少下游人员依据错误汇报继续操作的风险。现有材料支持这一工程方向，尚未证明它能在所有任务中稳定消除虚报。【Gemini 4 怎样训练到能做真实工程任务，Google DeepMind 的 Melvin Johnson 详解】【基于 LLM Wiki、OKF 与 Git 的 Agent 知识库：淘宝直播互动团队的 AI Coding 实践】

### 3. “更高效”正在分化为延迟、吞吐、预算与质量之间的具体取舍

材料事实： DeepSeek 优化后的最终配置相较 TP4 基线，平均端到端延迟下降 65.5% 至 4.70 秒，输出吞吐量达到每秒 2465 token；在其部署对比中，分离式延迟更低，共置式单 GPU 吞吐更高，分别为每秒 308 与 371 token。Envoy 则通过每分钟、每日 Token 限额、调用前估算和按会话或智能体累计消耗，治理运行预算。【优化 H20-3e 上 DeepSeek-V4.1-Flash 的分离式预填充-解码与共置服务】【Envoy 智能体网络栈：路由模型、Token 与 MCP】
