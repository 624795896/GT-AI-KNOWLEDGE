# 工程技巧

今日主线：AI 工程化的关注点正从“接入多少能力”转向“能否在明确约束下完成任务，并验证实际结果”。 本批材料分别展示了规格管理、知识检索、工具治理、执行控制与运行验证的实践；这些环节具有互补关系，但尚无充分证据证明它们已形成成熟的统一方案，或能普遍带来确定的成本收益。 这是跨来源分析推断，并非行业采用率结论。 【是不是引入某一个工具集，就算 SDD？（arch.md 开源）】【三个 AI 应用项目的工程复盘：编程智能体、新闻聚合与思想画廊】【800 个 MCP Server、5000 个工具，AI 智能体的“微服务危机”来了】【代码里明明配置了鉴权，服务却仍暴露公网：Shopify 不再相信代码仓库】

### 2. 工具与执行治理：规模扩大后，权限、追踪和停止能力成为基础设施

材料事实： Uber 的 MCP Gateway 管理 800 多个 MCP Server、5000 多个工具，以注册中心维护定义、Schema、所有权和启用状态，自动发现的新工具默认禁用，并通过代理对接既有协议。AgentTeams 则提供 Worker 会话追踪、执行瀑布图、停止、审批和交付验收。前者侧重工具供给与调用治理，后者侧重任务执行过程管理。【800 个 MCP Server、5000 个工具，AI 智能体的“微服务危机”来了】【AgentTeams 更新：全新工作台与官网，一键开启团队协作】

## 二、关键洞见

### 1. Agent 成熟度更应看“失败能否被识别和处置”

跨来源分析： 工具默认禁用、执行停止与审批、独立复核、连续无提升时回退，以及安全检测中的变异测试和金丝雀目标，分别作用于执行前、执行中和执行后。它们共同支持一个判断：生成方案之后，还需要相对独立的检查机制。【800 个 MCP Server、5000 个工具，AI 智能体的“微服务危机”来了】【AgentTeams 更新：全新工作台与官网，一键开启团队协作】【Fluid-Sinapis v0.1 发布：让 LLM+Agent 参与云原生缓存管理】【你和 AI 编程提效 10 倍的人，差了哪三层？】【代码里明明配置了鉴权，服务却仍暴露公网：Shopify 不再相信代码仓库】

落地建议｜分析推断： 优先自动化成功标准明确、动作有限、失败后容易恢复的任务，再依据失败识别率和恢复结果扩大自治范围。增加复核 Agent 是否有效，需要检验它能否发现规划者遗漏的问题；不能把某篇材料中的回退能力视为其他产品已经具备的功能。【你和 AI 编程提效 10 倍的人，差了哪三层？】【Fluid-Sinapis v0.1 发布：让 LLM+Agent 参与云原生缓存管理】
